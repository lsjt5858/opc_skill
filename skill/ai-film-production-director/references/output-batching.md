# AI 电影制片导演 交付物的分批输出

当请求的交付物较大，单次回复可能丢失镜头级细节、跳过资产或压缩 QC 时，使用分批输出。

## 何时分批

根据以下因素共同判断是否需要分批，不设固定镜头数或资产数阈值：

- **镜头数量**：当前输出能否逐镜完整展开，而不压缩或遗漏栏目；
- **资产引用复杂度**：跨镜角色、状态、道具、环境和文字策略是否需要分组才能准确追踪；
- **动作与声音密度**：时间段、动作层和声音层是否能在一批内保持清晰；
- **完整 QC**：单次输出能否为每个镜头保留完整 QC 和包级核验。

只要单次输出能完整保留资产引用、镜头细节和 QC，就不分批；小任务不分批。

## 分批计划格式

写大型输出前，先简短说明：

```text
我会分 {batch_count} 批输出，避免镜头细节被压缩：
- 第 {batch_index} 批覆盖范围：{具体资产、镜头 ID 或后期/QC 交付物}
- 分批依据：{镜头数量 / 资产引用复杂度 / 动作与声音密度 / 完整 QC}
- 下一批覆盖范围：{具体范围；最后一批写“无”}
```

批次数量与覆盖范围按项目实际复杂度确定，不套用默认镜头分组。

## 分批内容规则

- 第 1 批必须锁定 Production Spec、每镜生成模式、资产 ID、时间线和文字政策；后续批次不得静默修改这些已锁定内容，发现冲突时应显式停下并回报。
- 每一批开头声明本批覆盖范围，包括具体资产、镜头 ID 或后期/QC 交付物。
- I2V/参考驱动批次只重复实际存在、平台支持且当前镜头组需要的资产 token；纯 T2V 批次可重复不传给模型的资产设计台账，但不得包含或传入 token/UUID。
- 所有批次保持镜头 ID 稳定。
- 每批结尾写清楚下一批覆盖范围。
- 如果可以自动继续，就不要等待用户确认。
- 如果受回复长度或轮次中断限制无法继续，告诉用户下一步要请求的精确批次。

每个镜头的生成模式写法互斥，不得同时输出：

- **I2V/参考驱动**：仅在 Production Spec 已确认平台支持参考输入时使用，并只传入实际存在、平台支持且当前镜头需要的引用。
- **纯 T2V**：不传入 token、UUID、来源帧或资产引用；以完整文本连续性 DNA、开始状态和结束状态承载连续性。

若原定 I2V/参考驱动镜头的平台不支持参考输入，不得在当前批次静默省略引用继续生成。必须先在 Production Spec 和镜头卡中显式将该镜生成模式改为纯 T2V，重写对应提示词并重新通过对应阶段 Gate；否则保持阻塞或更换为支持参考输入的平台。

## 每个镜头的最低细节

不要把单个镜头压缩到低于这些字段：

- 生成模式与输入：I2V/参考驱动只上传并引用实际存在、平台支持且当前镜头需要的资产；纯 T2V 不传入 token、UUID、来源帧或资产引用，并完整写明文本连续性 DNA、开始状态和结束状态；
- 风格锁定；
- 声音规则；
- 当前状态下的资产锚点；
- 镜头组织；
- 机位与构图；
- 动作节奏；
- 尾帧；
- 铁律与负面约束；
- 后期文字/声音说明；
- QC。
