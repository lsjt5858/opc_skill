# AI Film Production Director 优化设计

## 1. 背景

现有 `skill/quan_zhan_dao_yan` 已覆盖连续性审计、制片计划、资产提示词、storyboard、keyframe、视频提示词包和提示词修补，但存在三个问题：

1. 目录名、frontmatter `name` 和 `agents/openai.yaml` 调用名不一致。
2. “全栈导演”边界过宽，容易被理解为同时承担文学创作、风格设计和所有视频生产任务。
3. 制片变量、阶段准入条件和最终提示词包质量门槛尚未形成统一契约。

本次优化将其重新定位为跨剧本、跨题材、跨风格、跨平台的 AI 电影制片与提示词包 skill。

## 2. 命名

- Skill ID：`ai-film-production-director`
- 目录：`skill/ai-film-production-director`
- 展示名：`AI 电影制片导演`
- 核心定位：把剧本、素材和制作约束转换成可执行的 AI 电影制片方案与视频提示词包。

建议 frontmatter：

```yaml
---
name: ai-film-production-director
description: Use when 用户需要规划或审查 AI 电影制作，尤其涉及剧本可生产性、跨镜头连续性、资产依赖、关键帧或可执行视频提示词包。
---
```

`description` 只描述触发条件，不概述完整工作流，避免调用方只按描述执行而跳过 skill 正文。

## 3. 目标

1. 建立统一、变量驱动的 AI 电影制片入口。
2. 强化剧本可生产性审计、连续性锁定和资产依赖规划。
3. 输出可直接执行、可追踪、可验收的视频提示词包。
4. 保留单 skill 入口，通过 references 按需加载控制上下文重量。
5. 支持不同题材、视觉风格、画幅和视频生成平台，不写死项目默认值。

## 4. 非目标

- 不从零创作小说或完整文学剧本。
- 不承担泛文案润色。
- 不绑定万物生、Seedance、可灵或其他特定平台。
- 不预设写实、动画、仙侠、悬疑等视觉风格。
- 不把未经审计的剧本机械转换成最终视频提示词。
- 不在本次优化中拆成多个独立 skill。

剧本修改只服务于可拍摄性、可生成性、时长控制、镜头覆盖和剪辑衔接。


### 5.1 `SKILL.md`

作为轻量总入口，只保留：

- 定位、适用范围和非目标；
- 请求模式路由；
- Production Spec 最小要求；
- 统一生产链；
- 阶段阻塞规则；
- reference 按需加载规则；
- 最终交付检查。

详细模板和操作规则保留在 references，不在主文件重复。

### 5.2 References

- `continuity-audit.md`：事实台账、连续性审计和剧本可生产性审计。
- `production-workflow.md`：Production Spec、场景/镜头规划、资产依赖、生成顺序和阶段关口。
- `prompt-patterns.md`：角色、道具、环境、storyboard、keyframe 和视频镜头提示词模式。
- `video-prompt-pack-template.md`：完整视频提示词包及单镜头固定栏目。
- `output-batching.md`：根据镜头数量、资产数量和复杂度动态分批。

## 6. 请求模式

Skill 选择满足用户需求的最小模式：

| 模式 | 典型输入 | 主要输出 | 读取 reference |
|---|---|---|---|
| 制片审计 | 剧本、资产表、提示词包 | 冲突、风险、锁定值、最小修改 | `continuity-audit.md` |
| 制片计划 | 剧本、大纲、制作约束 | Production Spec、镜头规划、资产依赖、阶段计划 | `production-workflow.md` |
| 资产提示词 | 明确资产需求 | 角色、道具、环境、keyframe 或单镜提示词 | `prompt-patterns.md` |
| 完整提示词包 | 剧本、素材、平台约束 | 完整 video prompt pack、后期清单、QC | `video-prompt-pack-template.md`，必要时组合其他 references |
| 提示词包修补 | 已有提示词包 | 保留正确内容后的最小修补 | 按缺陷类型读取 |

小任务不得自动展开完整端到端流程。

## 7. Production Spec 变量契约

每个项目先锁定或标注以下变量：

| 变量组 | 内容 |
|---|---|
| 故事 | 题材、时代、地点、人物关系、核心冲突、关键节拍 |
| 交付 | 总时长、画幅、分辨率、帧率、目标平台 |
| 视觉 | 媒介、写实度、色彩、光线、镜头特征 |
| 表演 | 情绪强度、肢体尺度、对白、口型 |
| 声音 | 对白、旁白、环境音、动作音、强调音、音乐策略 |
| 生成 | 模型、单次时长、参考输入能力、素材数量或格式限制 |
| 后期 | 字幕、UI、关键文字、合成、调色和声音交接 |

缺失变量按影响处理：

- **阻塞变量**：会改变故事逻辑或生产路径，必须询问或给出显式待确认方案。
- **可推断变量**：采用保守值，并标记为“推断”。
- **可延后变量**：不影响当前阶段，记录为待定，不阻塞工作。

不得把其他项目的画幅、时长、镜头数、风格或平台限制当作默认值继承。

## 8. 统一生产链

```text
输入与变量锁定
→ 剧本可生产性与连续性审计
→ 场景表和镜头卡
→ 资产依赖与生成顺序
→ Storyboard / Keyframe
→ 视频提示词包
→ 后期交接与 QC
```

### 8.1 可生产性审计

除事实连续性外，还检查：

- 无法直接视觉化的心理描写；
- 单镜动作、地点或身份变化过载；
- 台词时长超出镜头容量；
- 空间关系、视线或屏幕方向缺失；
- 关键文字依赖生成模型准确绘制；
- 情绪转折缺少可见表演和镜头覆盖；
- 结尾状态不能承接下一镜头。

审计不自动重写故事。默认输出问题、下游影响和最小修改建议。

### 8.2 资产依赖

- A 级：风格 bible、主角中性身份、核心道具、重复空环境。
- B 级：服装、年龄、伤痕、天气、表情和困难动作状态。
- C 级：storyboard、镜头起止 keyframe、插入镜头和视频提示词。

资产按复用和依赖关系生成，不按剧本出现顺序机械生成。

## 9. 阶段准入与错误处理

以下问题阻止生成受影响的最终视频提示词：

- 角色身份、年龄或人物关系冲突；
- 核心道具归属、尺寸、外观或状态不清；
- 场景几何无法支持规划镜头；
- 画幅、时长或平台能力互相冲突；
- 关键文字没有受控后期策略；
- 单镜头包含多个高风险动作、地点变化或摄影机任务；
- 提示词引用不存在的资产或虚构 UUID。

遇到阻塞时返回：

1. `阻塞项`
2. `下游影响`
3. `建议锁定值或最小解决方案`
4. `仍可继续完成的部分`

阶段状态分为：

- **通过**：无阻塞问题，可进入下一阶段。
- **有条件通过**：仅缺少非关键资产，可先做 storyboard 或测试镜头。
- **阻塞**：不得生成受影响的最终资产或视频提示词。
- **需拆镜**：当前镜头超出单次生成的可控范围。

## 10. 视频提示词包质量标准

### 10.1 包级标准

| 维度 | 通过标准 |
|---|---|
| 生产一致性 | 画幅、时长、平台限制和视觉规则与 Production Spec 一致 |
| 资产可追踪 | 每个引用 ID 都存在，状态变体明确，不编造 UUID |
| 镜头可执行 | 单镜头只有一个主要叙事节拍和一个主要摄影机运动 |
| 时间可验证 | 分秒动作覆盖完整时长，无空档、重叠或超时 |
| 剪辑可衔接 | 首尾状态、视线、屏幕方向、道具和光线可接续 |
| 后期可落地 | 关键文字、字幕、UI、声音和合成有明确交接 |

### 10.2 单镜头固定栏目

每条最终视频提示词保留十个独立栏目：

```text
【场景】
【运镜】
【动作】
【尾帧】
【音效】
【影像调性】
【表演要求】
【对白】
【反向锚定】
【后期与 QC】
```

字段无内容时写“无”，不得删除或合并。

### 10.3 单镜头硬标准

- 明确镜头故事作用。
- 只引用当前镜头实际需要且已存在的资产。
- 分开描述主体运动、摄影机运动和环境运动。
- 动作顺序与总时长一致。
- 尾帧包含人物位置、视线、道具状态、光线和剪辑接口。
- 音效按环境音、动作音、强调音组织；音乐由项目变量决定。
- 表演落实到呼吸、视线、姿态和微动作。
- 关键文字默认后期合成。
- QC 使用可观察的通过/失败条件。

## 11. 输出分批

分批依据是复杂度，不是固定镜头编号：

- 镜头或资产数量较多；
- 同时交付制片计划、资产提示词和最终视频提示词；
- 单镜头需要复杂动作、声音、尾帧或后期说明；
- 单次输出会压缩 QC 或遗漏资产。

每批先声明覆盖范围。后续批次不得修改已经锁定的 Production Spec、资产 ID、时间线和文字政策。

## 12. 验证方案

Skill 修改采用 RED、GREEN、REFACTOR：

### 12.1 RED：记录当前失败

对当前版本运行以下场景，记录是否出现直接编造、平台默认值污染、无关 reference 过载或缺少阻塞：

1. 只提供一句故事梗概。
2. 提供存在年龄和道具冲突的剧本。
3. 提供完整剧本、素材目录和平台限制。
4. 只请求一个角色身份图或 keyframe。
5. 提供部分正确、部分缺陷的已有提示词包。
6. 分别输入现实剧情、仙侠、悬疑和动画题材。
7. 切换不同模型的时长和参考输入限制。

### 12.2 GREEN：验证目标行为

- 信息不足时先建立变量状态，不直接编造最终提示词包。
- 冲突影响下游时停止相关阶段并给出最小解决方案。
- 完整项目按统一生产链输出。
- 单资产请求只加载必要 reference。
- 修补模式保留正确内容，不全盘重写。
- 跨题材时流程稳定，但不强加风格。
- 切换平台时只改变变量和镜头拆分。

### 12.3 REFACTOR：关闭漏洞

根据测试中出现的新错误补充最小规则，再重跑相同场景。不得为了通过单个案例写入项目专属事实。

### 12.4 静态回归检查

- 目录、frontmatter 和 `openai.yaml` 统一使用 `ai-film-production-director`。
- 清除旧的 `wanwusheng-ai-film-director` 调用名。
- frontmatter 名称只含字母、数字和连字符。
- description 只描述触发条件。
- 所有引用的 reference 文件存在。
- 不写死平台、风格、画幅、总时长或镜头数。
- 单镜头模板十个栏目完整且顺序稳定。
- 主 `SKILL.md` 保持轻量，细节按需加载。

## 14. 验收标准

完成后必须满足：

1. 用户可以通过 `$ai-film-production-director` 正确调用。
2. 对小请求只执行最小模式，不输出无关完整流程。
3. 对完整项目能形成从 Production Spec 到 QC 的闭环。
4. 对关键冲突能够阻塞下游，而不是悄悄选择答案。
5. 提示词包符合十栏目结构和六类质量标准。
6. 任意题材、风格和平台均通过变量适配，不依赖隐含默认值。
7. 现有连续性审计、资产规划、keyframe、提示词修补能力不回退。
