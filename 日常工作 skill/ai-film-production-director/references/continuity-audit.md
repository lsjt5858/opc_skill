# 连续性审计

在根据剧本生成依赖提示词，或审查已有提示词包前，先使用这份清单。

## 1. 故事事实台账

只提取事实，不加修饰：

| 领域 | 检查项 |
|---|---|
| 时间线 | 精确年份、经过时长、闪回顺序、季节、一天中的时间 |
| 角色 | 姓名、每个时期的年龄、关系、职业、身体经历 |
| 地点 | 地名、室内/室外、移动逻辑、重复出现的空间特征 |
| 服装 | 年代、服装状态、天气/工作/受伤造成的变化 |
| 道具 | 归属者、尺寸、年代、材质、损坏、内容物、每场状态 |
| 伤痕 | 身体左右侧、原因、可见状态、治疗、后续疤痕或行动限制 |
| 天气/光线 | 雨/干燥状态、阳光方向、湿度连续性 |
| 证据文字 | 日期、价格、姓名、手机 UI、收据、标签、手写字 |
| 机构 | 医院/诊所/养老院/学校/公司名称与功能 |

## 2. 年龄、算术与身份检查

- 用年份计算年龄，不要分别接受描述性年龄。
- 检查所有时期中的父母/子女年龄差。
- 验证“年轻版/年老版”描述是否保留身份锚点。
- 检查核心道具的物理尺寸是否适配其归属者和动作。
- 检查同一物品是否被误换成相似类别，例如成人布鞋变成儿童运动鞋。
- 检查购买日期、学年、技术、车辆、服装或建筑是否符合故事年代。

## 剧本可生产性

在生成依赖资产、最终 keyframe 或视频前，逐镜检查：

- **不可直接视觉化**：把心理描写、判断或抽象结论改写为可见动作、表演反应或声音线索；无法改写时阻塞该镜。
- **动作过载**：单镜包含多个独立动作、地点变化或身份变化时，标记为需拆镜，不让一次生成承担多个叙事单位。
- **台词容量**：对白或旁白无法在计划时长内自然完成时，阻塞时长锁定或拆分镜头，不以异常语速强行容纳。
- **空间关系**：入口、出口、站位、视线或屏幕方向缺失时，不生成依赖这些关系的最终 keyframe；先补齐 blocking 和拍摄方向。
- **关键文字**：所有必须准确可读的故事文字都要指定后期排版、合成与校对策略，不依赖生成模型直接写字。
- **剪辑接口**：每镜开始状态必须明确；结束状态只由镜头卡 `Canonical tail state / 权威尾帧定义` 持有，并以结构化 `Camera/composition`（景别、机位/角度、画面布局）、`Character terminal state`（位置、姿态、朝向、表情、手部、动作完成状态）、`Environment terminal state`（环境运动、天气、粒子、光线终态）及道具持有/状态/方向、视线、下一镜剪辑接口完整记录，以便与相邻镜头衔接。

每个阶段或一次完整审计的**整体结论/准入结论**使用且只使用以下四态。它回答“当前交付物能否进入受影响的下游阶段”，不是单个问题的处理进度：

- **通过**：信息完整、自洽，可进入下游。
- **有条件通过**：存在已记录的安全推断或后期策略，可继续但必须携带条件。
- **阻塞**：关键事实或生产条件缺失、冲突，解决前不得进入受影响的下游步骤。
- **需拆镜**：当前镜头容量或变化超限，拆成独立镜头后重新审计。

单个问题使用独立的 `Status` 记录处置进度，取值为 `待处理 / 待确认 / 已缓解 / 已解决`。问题需要拆镜时，在 `Recommended action` 中写 `需拆镜`；只有该问题决定当前整体准入结果时，整体结论才同时使用 `需拆镜`。

## 3. 核心道具状态台账

每个故事节拍一行：

| 场景/镜头 | 归属者 | 状态 | 损坏/标记位置 | 容器 | 持有者 | 画面位置 |
|---|---|---|---|---|---|---|

对反复出现的磨损、污渍、折痕、刻字、断边和扣件使用精确锚点。如果故事区分两个相似物品，明确写出它们的差异。

## 4. 关键文字政策

给文字分类：

- **故事关键且需要可读**：收据、信件、日期、价格、证据、标题。使用受控排版或合成图层。
- **附带且可模糊**：手机屏幕、远处横幅、文件。除非故事需要，否则保持不可读。
- **禁止**：意外字幕、水印、logo、扭曲标签。

不要依赖图像生成器输出精确关键文字。应先生成纸张/屏幕/物体材质，再后期合成经过校对的文字。

## 5. 冲突严重程度

`Severity` 只表示问题影响程度，与处置进度和整体准入结论分开：

- **Blocker**：改变身份、时间线、归属、情节逻辑、最终画幅或重复核心道具。停止生成依赖提示词。
- **Major**：缺少重复角色、地点、服装状态或场景覆盖。最终 keyframe 前补齐。
- **Minor**：可逆推断的视觉选择，例如中性墙面颜色。提出建议并标注为推断。

## 6. 审计输出格式

```text
Audit scope: {阶段、镜头或交付物范围}
Overall conclusion: 通过 / 有条件通过 / 阻塞 / 需拆镜
Conditions / blocking summary: {通过时写“无”；否则列出准入条件、阻塞项或拆镜要求}

ID: CONT-01
Severity: Blocker / Major / Minor
Source facts: {事实 A} vs {事实 B}
Downstream impact: {受影响资产/镜头}
Recommended lock: {一个自洽锁定值}
Alternative: {仅在确有价值时提供}
Recommended action: {确认 / 补充 / 返修 / 需拆镜 / 其他明确动作}
Status: 待处理 / 待确认 / 已缓解 / 已解决
```

每个问题重复 `ID` 到 `Status` 字段；`Overall conclusion` 只在审计汇总层记录一次。`Severity` 不随处置进度自动改变；问题解决后保留原严重程度并把 `Status` 更新为 `已解决`，以保留审计轨迹。

不要在后续提示词里偷偷选择一个值来掩盖冲突。先记录解决方案，再一致使用。
