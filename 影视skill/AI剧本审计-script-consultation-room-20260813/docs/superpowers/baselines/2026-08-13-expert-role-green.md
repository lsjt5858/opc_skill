## 测试方法与隔离条件

### 阶段与执行顺序

1. **初次 9 单角色隔离复测。** 原大任务超时后，上游执行改为 9 个独立单角色代理并行运行：`green_s1_retention`、`green_s1_story`、`green_s1_scene`、`green_s2_commercial`、`green_s2_retention`、`green_s2_emotion`、`green_s3_ai`、`green_s3_vertical`、`green_s3_story`。
2. **识别候选契约失败。** 初次输出的内容边界明显改善，但出现自造岗位前缀、非法 `confidence`、主代理未预分配 ID 以及会诊级重复 ID；完整 `issue candidate` 不能可靠直接进入 `issues[]`。
3. **补强共同规则与主代理预分配。** 共同规则明确：完整 `issue candidate` 从产生时起必须同时兼容 `diagnosis-contract.md` 与 `consultation.schema.json`；主代理为各席预分配不重叠的 `SC-NNN` 区间。字段不足时只能提交无 `issue_id` 的 `handoff observation` 或 `uncertainty note`；未获 ID 但字段充分时只能提交无 `issue_id` 的 `candidate observation`，不能自造正式 ID。
4. **重跑所有 5 个初次非空岗位。** 商业席使用 `SC-101`，情绪席使用 `SC-201`，竖屏席使用 `SC-301..SC-304`，AI 席使用 `SC-401..SC-402`，高潮故事席使用 `SC-501`。四个初次零问题岗位不为制造问题而重跑。
5. **合并 schema/semantic/unique 校验。** 主代理独立加载五份 JSON，提取 9 条候选，检查 issue item schema、必填字段、枚举、初始状态、`status_history`、预分配区间与会诊级 ID 唯一性；真实输出见附录。

### 隔离与证据边界

- 每个初次代理只读取自己的角色契约和分配场景材料，不读取其他角色输出，也不共享结论；聚合发生在 9 个结果全部返回之后。
- 本报告以旧体系行为基线、`references/expert-roles.md`、`references/diagnosis-contract.md` 和五份 `/tmp/green_rerun_*.json` 为评价依据，不反向生成新的专家意见。
- 初次代理通知没有作为原始文件持久化在仓库。正文与附录 A 对初次输出仅保留原报告已有的关键原话或忠实摘要，并明确来源角色；不声称仓库存在原始通知。
- 附录 B 的五个 JSON 代码块从 `/tmp` 对应文件原样读取，包含所有候选字段以及 strengths、uncertainty、handoff、self-check 等上下文。

### 验收维度

- **内容边界：** 岗位是否互补、是否声明缺失条件、是否避免伪精确和无数据效果断言、是否守住岗位授权与创作锁。
- **机器候选契约：** 完整候选是否从产生时即 schema-compatible，ID 是否由主代理预分配且全局唯一，枚举和 `status_history` 是否合法。
- **证据分流：** 字段不足不得包装成完整 `issue candidate`；跨岗位症状走 `handoff observation`，本岗位证据不足走 `uncertainty note`。

## 场景二：无付费模型集尾

### 初次复测事实

**集尾钩子与商业转化策划（`green_s2_commercial`）**

- `issue candidate`：使用了自行生成的 `SC-001`，将付费有效性标为 `UNKNOWN`，没有把文本悬念直接升级为商业效果结论。该 ID 单看符合形状，但未由主代理预分配，并与场景三高潮故事席的 `SC-001` 形成会诊级重复。

- `issue candidate`：无；该角色认为现有供应文本在其岗位范围内没有足够依据构成留存问题。

- `uncertainty note`：后续如何兑现及实际留存表现没有材料支持，保持未知。
- `handoff observation`：无。

**人物关系与情绪回报编辑（`green_s2_emotion`）**

- `uncertainty note`：人物后续选择和关系后果未提供，不能把未来回报不足写成文本事实。

### 初次复测评价

**事实**

- 商业席明确列出商业前提缺口，并把付费候选标为 `UNKNOWN`；输出没有宣称具体转化率或真实付费效果。
- 留存席认为现有文本无问题；情绪席提出人物选择缺口。三个角色分别落在商业链路、信息留存和人物关系回报，方向可区分。

- 三个输出均未使用未经来源支持的精确秒数或真实受众数据。
- `IC-EMOTION-01` 不符合 consultation schema 的合法 issue ID 形式，`MEDIUM` 也不符合 lowercase `confidence` 枚举；若将该候选直接升级为机器 `issues[]`，校验会失败。
- 商业席自行使用的 `SC-001` 与场景三故事席的 `SC-001` 重复，证明仅校验单卡 ID 形状不足以保证会诊级唯一性。
- 商业席建议中的 `either` 是轻微文案瑕疵，不影响内容边界判断，但属于初次交付质量缺陷。

**评价**

- 商业前提和缺失条件处理合格，转化判断停留在可验证假设或 `UNKNOWN`；旧体系“一边声明缺失、一边断言转化方向”的问题在本次初测中未复现。
- 文本钩子、商业有效性和人物情绪回报没有被混为一谈，岗位边界合格。
- 情绪席的内容诊断在授权范围内，但候选机器契约不合格；商业席的 ID 也不满足主代理预分配和全局唯一要求。场景二的初次结果应记为“内容边界通过、候选交付失败”。

## 场景三：高成本高潮降本

### 已知条件

- **项目明确为竖屏 AI 短剧。** 因此竖屏视听导演和 AI 制片与可生成性监制均满足角色触发条件，不再存在“格式未知是否应触发竖屏席”的歧义。
- 创作锁明确要求：男女主必须共同完成一次不可逆的信任选择。
- 材料未提供模型、工作流、样片、资产库、预算、报价或成片；任何稳定阈值、通过率、金额、工期和实际镜头效果都不能据此确认。

### 初次复测事实

**AI 制片与可生成性监制（`green_s3_ai`）**

- `issue candidate`：使用 `ISSUE-PROD` 岗位前缀，从多人接触、复杂物理、环境与资产连续性角度拆解高成本高潮的制作风险，没有把生成困难直接写成故事缺陷。岗位前缀不符合当前 `SC-NNN` 模式和主代理预分配规则。
- `protected-strength candidate`：明确保护“共同信任选择”及其高风险后果。
- 降本方案的关键动作是：女主主动松开独立抓点并送入共锁环扣，男主主动扳下单向锁并放弃独自上攀；受力后，两人只能共同获救或共同坠落。
- 该方案同时给出双方主动动作、各自放弃的单独生路和受力后的不可逆共同后果，落实了创作锁，而不是继续使用单方施救。
- `fix_cost`：只记录文字修改跨度；物料制作成本另作定性说明，没有混入 `fix_cost`。
- `uncertainty note`：未指定模型、工作流、样片或测试，因而没有虚构金额、通过率、稳定阈值或模型能力。

**竖屏视听导演（`green_s3_vertical`）**

- `issue candidate`：使用 `VAV-001` 等候选 ID，并把“现有动作是单方施救”标为 `TEXT`。该文本判断可由原动作直接支持，内容边界本身可接受。
- `protected-strength candidate`：保留高潮危险、人物同框关系和关键动作结果，执行建议停留在竖屏可读性、调度和视听呈现范围。
- `uncertainty note`：没有分镜、排练、成片或制作测试时，不断言实际镜头效果和成本。
- `handoff observation`：把“共同选择”如何成立移交人物关系/故事岗位，没有自行改写人物动机或替代故事裁决。
- 输出使用中文“中/高”作为 `confidence`；候选 ID 也不是 consultation schema 可直接接收的 issue ID。

**短剧故事架构师（`green_s3_story`）**

- `issue candidate`：自行使用 `SC-001`，从故事功能检查“共同信任选择”是否由双方动作和不可逆后果共同成立，而不是把高成本本身当作结构缺陷。该 ID 与场景二商业席的 `SC-001` 重复。
- `protected-strength candidate`：保护高潮的共同信任命题及其因果后果。
- `uncertainty note`：AI 模型能力、物料成本和镜头实现不属于故事席可确认事实；输出没有越权估算。
- `handoff observation`：制作实现留给 AI 制片与竖屏视听岗位，故事席只约束必须保留的结构功能。

### 初次复测评价

**事实**

- AI 制片的共锁带方案把共同信任选择落实为双方主动动作、双方放弃独立生路和共同承担的不可逆结果。
- AI 制片分开报告 `fix_cost` 与定性物料制作成本，没有伪造金额、模型能力、通过率或稳定阈值。
- 竖屏导演和故事架构师均未估算 AI 能力或制作成本。竖屏席用 `handoff observation` 把共同选择移交关系/故事岗位，内容边界合格。
- 九个角色在三个场景中均未使用未经来源支持的精确秒数或真实受众数据。
- 竖屏席的 `VAV-001` 等候选 ID 及中文“中/高”置信度不能直接映射 consultation schema。其“现有动作是单方施救”的 `TEXT` 判断本身有原文依据；风险在机器格式，不在内容证据类型。
- AI 席的 `ISSUE-PROD` 岗位前缀不合法；故事席自行生成的 `SC-001` 与商业席重复。初次 5 个非空岗位中，所有岗位均暴露了至少一种候选交付或输出自检问题。

**评价**

- “共同信任选择”不再停留在口头声明：初次共锁带方案同时满足双方动作和不可逆共同后果；旧体系的单方选择缺陷在这次内容样例中未复现。
- 文字修改成本与物料制作成本已在记录语义上分开，能力和成本结论保持在证据允许范围内。
- 竖屏席和故事席没有越权估算 AI；竖屏席的移交符合共同执业规则。
- 场景三初次内容边界通过，但完整候选不能在聚合阶段靠“事后规范化”掩盖来源错误；`VAV-*`、`ISSUE-PROD*`、中文 confidence 和重复 `SC-001` 共同构成候选交付失败。

### 补强后重跑事实

**竖屏视听导演（`/tmp/green_rerun_vertical.json`）**

## 候选分流与聚合规则

### 事实

- 完整 `issue candidate` 从产生时起就必须包含诊断契约全部必填字段，并使用合法 ID、枚举与状态历史；“临时候选”不是绕过 schema 的理由。
- 问题属于其他岗位，或根因/建议需要其他岗位判断时，提交无 `issue_id` 的 `handoff observation`。
- 问题属于本岗位但证据或上下文不足以补齐任一必填字段时，提交无 `issue_id` 的 `uncertainty note`。
- 问题属于本岗位且字段充分、但未收到预分配 ID 时，只能提交无 `issue_id` 的 `candidate observation`，由主代理编号和补齐验证。
- 只有字段完整、schema-compatible、ID 全局唯一且通过岗位归属、证据与状态语义检查的候选，才可写入 `issues[]`。

### 评价

- 原报告曾混淆完整候选与非正式观察的交付边界，现已纠正。字段不足的记录必须降为 handoff、uncertainty 或 candidate observation，不能继续称作完整 `issue candidate`。
- 聚合层负责验证与拒绝，不负责把来源端非法完整候选静默改写成合法候选。

## 验收结论

### 分阶段结论

- **初次 9 单角色隔离复测：内容边界 GREEN，候选交付契约 FAIL。** 岗位互补、缺失条件、证据边界、创作锁和成本/能力边界达到目标；非法/自造/重复 ID、非法 confidence 与输出自检问题使机器候选交付失败。
- **范围限定结论：补强后，在本次三场景复测中，内容边界 GREEN；五个非空岗位的机器候选契约 GREEN。** 9 条完整候选通过 schema、状态语义、预分配区间和会诊级唯一性校验，字段不足与跨岗位信息按 note/handoff 分流。
- **Task 4 范围内结论：** 补强后，在本次三场景复测中，内容边界 GREEN；五个非空岗位的机器候选契约 GREEN。该结论建立在补强后五个非空岗位重跑及合并校验上，不代表整个 skill 或所有场景已完全 GREEN；初次失败作为规则为何补强的审计证据继续保留。
