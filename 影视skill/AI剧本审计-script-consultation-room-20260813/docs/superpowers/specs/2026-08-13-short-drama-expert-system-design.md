# 短剧商业增长专家体系重构设计

## 目标

把现有“角色简介式”专家组升级为可执行的短剧开发会诊制度。每个专家必须有明确的审查对象、专业方法、证据门槛、标准交付件和权限边界，避免角色扮演式泛评、重复诊断和凭空推测观众反应。

本次改动聚焦 `references/expert-roles.md`，并同步调整 `SKILL.md` 中的专家选择、全面会诊和聚焦会诊组合。机器记录的字段名、枚举值和 JSON Schema 不变。

## 设计原则

1. **岗位服务决策，不服务人设。** 专家名称必须对应真实审查职责和可区分的决策权。
2. **核心席常驻，条件席按证据触发。** 不为凑人数运行无关专家。
3. **每条结论都能进入问题卡。** 专家输出必须包含位置、原文锚点、因果诊断、影响、修改方向和风险。
4. **商业指标不伪精确。** 没有可靠时长、平台数据、付费模型或分集策略时，相关判断必须标为 `INFERENCE` 或 `UNKNOWN`。
5. **增长不凌驾于戏剧。** 留存、付费和低成本方案不得通过破坏因果、人物可信度或创作锁实现。
6. **总监只裁决，不追加诊断。** 用户保留接受、拒绝、搁置和改写授权。

## 专家架构

### 四个核心席

#### 1. 短剧故事架构师

- 审查对象：核心戏剧引擎、主角行动目标、阻力升级、因果链、单集任务、反转与兑现。
- 核心方法：承诺—阻碍—选择—后果链；伏笔—回收账本；反转前后信息权限核验。
- 标准交付：结构性问题卡、因果根节点、必须保留的戏剧承诺、修改依赖顺序。
- 禁止越权：不得用“更爽”替代人物动机，不得直接改写对白或镜头。

#### 2. 留存与信息策略师

- 审查对象：开场承诺、活跃观众问题、信息差、预期更新、滑走风险、节拍信息增量。
- 核心方法：问题开启/升级/延迟/兑现表；节拍级预期变化审计；承诺兑现距离检查。
- 标准交付：流失风险点、缺失的信息动作、留存修复方向及其叙事代价。
- 禁止越权：没有可靠时间码时不得声称精确秒数；不得把快剪、吵闹或信息堆积等同于推进。

#### 3. 人物关系与情绪回报编辑

- 审查对象：欲望、关系权力、情绪蓄压、共情依据、爽点/虐点、高潮释放与余韵。
- 核心方法：人物欲望—恐惧—选择矩阵；关系权力变化表；情绪触发—升级—回报链。
- 标准交付：情绪断点、关系失真点、未挣得的爆发、应保护的表演与关系资产。
- 禁止越权：不得把强刺激自动判为高情绪价值，不得强迫所有题材服从同一情绪曲线。

#### 4. 场景与对白执行编辑

- 审查对象：场景目标、节拍动作、冲突转移、潜台词、对白效率、进入/退出点和可演性。
- 核心方法：场景前后状态差；对白动作标注；可见动作与解释性对白对照；重复信息清点。
- 标准交付：可定位的场景执行问题、动作化方向、对白压缩原则和表演风险。
- 禁止越权：不得只做金句润色，不得在根因未解决时修饰症状。

### 五个条件席

#### 5. 集尾钩子与商业转化策划

- 触发条件：连载、付费短剧、用户要求追更/卡点/转化分析，或提供明确商业模型。
- 审查对象：集尾未完成动作、下一集增量承诺、免费/付费边界、回报间距和集群节奏。
- 专业约束：区分悬念、信息扣留和生硬截断；没有付费策略时不得虚构转化结论。

#### 6. 竖屏视听导演

- 触发条件：竖屏项目、镜头/调度问题、视觉化不足、复杂动作或表演空间问题。
- 审查对象：竖屏构图、视觉信息优先级、调度、动作可读性、声音叙事和表演空间。
- 专业约束：不按分镜数量衡量节奏，不以昂贵镜头替代戏剧功能。

#### 7. AI 制片与可生成性监制

- 触发条件：AI 生成、低成本制作、多角色/多场景、复杂连续性或生成难度评估。
- 审查对象：角色一致性、服化道资产、手部与精细互动、复杂动作、场景复用、连续性和声音。
- 专业约束：必须分别报告文字修改成本和物料制作成本；降本方案必须保留戏剧功能。

#### 8. 平台策略与内容风险顾问

- 触发条件：指定平台/受众、题材边界、伦理争议、内容安全或发行适配问题。
- 审查对象：平台语法、目标人群预期、题材承诺、伦理风险、误导与潜在合规问题。
- 专业约束：不得把个人偏好包装成平台规则；无法确认的政策性判断标为 `UNKNOWN`。

#### 9. 逻辑连续性审计师

- 触发条件：复杂反转、悬疑、多人信息差、长线设定、时间线、身份秘密或重大修改。
- 审查对象：时间线、空间连续性、信息权限、设定一致性、因果作弊、强行降智和修复副作用。
- 专业约束：只攻击可证明的逻辑断裂；不得因“不喜欢”而把选择判为漏洞。

### 裁决席

#### 10. 剧本总监

- 输入：去重问题卡、根因图、重大争议、验证过的原文证据、创作锁和用户约束。
- 职责：驳回弱证据，归并根因，判定真实争议，选择一个专家方案，解释主要替代方案为何落败，排序修复依赖。
- 禁止事项：不得新增独立诊断；不得代用户设置 `accepted`、`rejected` 或 `deferred`；不得授权改写。

## 统一角色契约

`expert-roles.md` 中每个角色统一使用以下结构：

1. **任务授权**：该岗位唯一负责什么。
2. **必须回答的问题**：3–6 个可验证问题。
3. **专业方法**：使用什么分析框架，不使用哪些伪指标。
4. **证据门槛**：什么可标为 `TEXT`，什么只能是 `INFERENCE` 或 `UNKNOWN`。
5. **标准交付件**：该专家必须返回哪些结构化内容。
6. **禁止越权**：明确与其他岗位的边界。
7. **交叉质询触发条件**：什么分歧足以升级为重大争议。

所有诊断专家最多提交五个高价值问题、三个受保护优点和一个“当前最大不确定性”。允许零个 P0/P1。

## 专家选择规则

- `LIGHT`：至少两个核心席；只运行与问题直接相关的条件席。
- `STANDARD`：四个核心席中至少三个，加必要条件席和逻辑连续性审计。
- `DEEP` 全面会诊：四个核心席全部运行；条件席依据平台、商业模型、制作方式和剧情复杂度触发，不再机械要求“全部专家”。
- 剧本总监不计入独立诊断专家数量，且只能在诊断完成和证据复核后运行。

## 主流程同步

1. 重写 `references/expert-roles.md`，使用统一角色契约。
2. 更新 `SKILL.md` 的专家数量、DEEP 规则、聚焦面板和无子代理降级方案。
3. 保留 `references/diagnosis-contract.md`、`report-template.md` 和 `consultation.schema.json` 的现有机器字段。
4. `mode.experts` 继续记录实际运行的岗位名称，不增加固定枚举，保持旧记录兼容。
5. 不新增“观众代表”角色。观众反应必须由文本触发、信息变化和情绪依据推导，禁止无证据扮演观众。

## 异常与缺失信息处理

- 无时间码：使用场景/节拍 ID 和原文锚点，不推测秒数。
- 无商业模型：商业转化结论降级为假设，并明确缺失的免费/付费边界。
- 无平台信息：不运行平台规则式结论；只报告跨平台叙事风险。
- 无制作方案：AI 制片只报告风险区间和关键不确定性，不虚构预算。
- 专家之间只有偏好差异、没有材料影响：不创建争议。

## 验证方案

### 基线失败特征

现有角色文件容易产生以下低质量输出：

- 多个专家重复说“节奏慢”“动机不足”。
- 增长专家在无时间码时编造前三秒/十秒结论。
- 观众代表用主观感受替代文本证据。
- AI 制片只列“多人、手部、复杂动作难生成”，没有功能保留方案。
- 总编剧用多数意见代替裁决。

### 改后验收场景

1. **无时间码的开场片段**：输出节拍锚点，不出现虚构秒数；三位专家的审查对象不重复。
2. **无付费模型的连载短剧**：商业转化策划明确标注未知条件，不编造卡点转化效果。
3. **高成本关键高潮**：AI 制片提供保留戏剧功能的降本方案，并单列文字成本与物料成本。
4. **悬疑反转争议**：逻辑审计检查信息权限，故事架构师检查戏剧收益，总监只裁决已有方案。
5. **证据不足的成熟稿件**：允许没有 P0/P1，不为显示专业而制造问题。

验收标准：岗位输出可区分、每条问题可进入现有问题卡、无越权状态操作、无伪精确数据、主流程引用的专家名称与角色文件一致。
