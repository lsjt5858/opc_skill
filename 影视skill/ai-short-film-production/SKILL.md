# AI 精品短片前期制作

把零散创意逐步编译成连续、一致、可执行的短片视觉资产包。保持单一入口，但按当前阶段只加载必要参考，避免一次输出整套流水线造成冗长。

## 能力边界

覆盖：

1. 剧本解析：人物、场景、道具、时间线、情绪节点、剧情节拍、关键时刻。
2. Visual Bible：世界观、类型、摄影、构图、色彩、光线、材质、画幅、后期。
3. Bible Forge：Character / Scene / Object Bible。
4. Narrative Engine：Asset Priority、Story Importance、Emotion Library、Shot Library。
5. Prompt Builder：角色图、场景图、道具图、剧情关键帧、特写、分镜图和视频生成前镜头提示词。
6. Production Orchestrator：资产依赖、生成顺序、一致性锁、连续性检查与交付清单。

不执行图片或视频生成，不虚构已生成结果。

## 核心原则

- **延续优先**：用户已有内容是当前项目事实；除非内部冲突或用户要求重做，不覆盖已确认设定。
- **最小推进**：判断当前阶段，只完成用户要求及其必要前置，不机械输出全部模块。
- **缺口补全**：信息不足但不影响创作时，做少量合理假设并标记；会改变故事核心、人物身份、时代地域或视觉方向时再询问。
- **先锁资产再组镜头**：剧情图和分镜必须引用已锁定的角色、场景、道具与视觉规则。
- **叙事优先**：画面服务剧情；生成预算按资产优先级和剧情重要度分配，而不是平均分配。
- **结构化但可读**：默认给创作者可直接使用的中文内容；只有用户要求或需要交接时才附 YAML。
- **提示词可执行**：每条提示词写清主体、动作、环境、情绪、镜头、光线、色彩、材质、一致性锚点、画幅和负面约束。

## 输入阶段识别

每次先在内部判断 `current_stage`，不要把分类过程长篇展示给用户。

| 输入特征 | 当前阶段 | 本轮重点 |
|---|---|---|
| 一句话创意、主题、梗概 | concept | 故事核心、人物关系、冲突、结局方向；必要时发展为短剧本 |
| 完整或部分剧本 | script | 解析实体、节拍、时间线、关键时刻 |
| 风格词、参考片、时代地域、画幅 | visual | 建立或修订 Visual Bible |
| 人物描述、定妆需求 | character | Character Bible 与角色图提示词 |
| 地点、空间、置景描述 | scene | Scene Bible 与场景图提示词 |
| 关键物件、物证、信物 | object | Object Bible 与道具图/特写提示词 |
| 情绪递进、重点镜头、资源取舍 | narrative | 优先级、重要度、情绪曲线、镜头策略 |
| 场次、镜头表、分镜草稿 | storyboard | 镜头拆分、连续性和分镜图提示词 |
| “提示词”“出图方案”“制作包” | deliverable | 缺口检查后输出指定提示词包 |
| 修改意见或上一轮产物 | revision | 定位受影响项，局部更新并传播依赖 |

若同时命中多个阶段，选择最靠后的可执行阶段，同时补齐必要前置。例如用户提供剧本并要分镜：先做最小剧本解析和一致性设定，再输出分镜，不必展示冗长的全部 Bible。

## 工作流

### 1. 读取与定位

1. 提取用户本轮目标和已有素材。
2. 识别当前阶段、已有成果和缺失前置。
3. 区分已确认事实、创作性补全和待确认决策。
4. 选择本轮最小输出范围。

### 2. 按需读取参考

- 处理剧本、Visual Bible、三大 Bible 时，读 `references/bibles.md`。
- 处理优先级、剧情重要度、情绪、镜头、分镜时，读 `references/narrative.md`。
- 生成任何提示词包、检查依赖或一致性时，读 `references/prompts-and-delivery.md`。
- 需要完整字段或 YAML 交付时，读 `references/schemas.md`。

不要无条件读取所有参考文件。

### 3. 创作与编排

默认依赖顺序：

```text
剧本/梗概
→ Script Breakdown
→ Visual Bible
→ Character / Scene / Object Bible
→ Asset Priority + Story Importance
→ Emotion Curve + Shot Strategy
→ 角色/场景/道具基础提示词
→ 剧情关键帧与特写提示词
→ 分镜图提示词
→ 视频生成前镜头提示词
```

可以局部进入，但下游输出必须具备足够的上游锚点。

### 4. 一致性检查

每次生成下游内容前检查：

- 角色：年龄、脸部锚点、体型、发型、服装阶段、配饰、动作习惯、心理阶段。
- 场景：空间布局、门窗方位、固定家具、年代痕迹、时间、天气、光源方向。
- 道具：唯一 ID、尺寸、材质、颜色、结构、磨损、持有者和所在位置。
- 连续性：前后镜头人物站位、视线、轴线、动作接点、衣着、伤痕、道具状态、光线与时间。
- 风格：画幅、摄影方式、色彩、颗粒、真实度与禁用风格。

发现冲突时明确列出，不静默改写用户事实。

## 输出策略

### 默认响应结构

按当前任务裁剪，不强制输出空章节：

```markdown
## 当前阶段
一句话说明本轮定位及继承内容。

## 本轮产出
实际创作内容。

## 一致性锚点
仅列本轮下游需要固定的关键设定。

## 下一阶段接口
列出本轮产物可直接进入的下一步，不以提问收尾。
```

### 交付粒度

- **快速模式**：用户只要方向时，给 1 个主方案和必要锚点。
- **标准模式**：默认；产出当前阶段的完整可用内容。
- **制作包模式**：用户要求完整、全部、交付包时，输出项目摘要、所有 Bible、叙事计划、资产清单、提示词包、分镜和连续性检查。

### 提示词语言

默认提供：

1. 中文导演版：便于审阅创作意图。
2. 结构化生成版：适合复制到图像模型。

仅当用户要求英文或具体模型格式时提供英文/模型适配版。不要假设 Midjourney、即梦、可灵、Runway 等特定模型。

## 完成标准

本轮产物应满足：

- 与用户已有故事和设定连续。
- 当前阶段目标完整，不夹带不必要的大量下游内容。
- 每个资产有稳定 ID，可被后续镜头引用。
- A 级资产和五星剧情节点得到更细提示词与更多视角。
- 情绪通过可见表演细节表达，不只写“悲伤/开心”。
- 镜头术语服务叙事动机，不堆砌专业词。
- 分镜引用明确的角色、场景、道具和连续性状态。
- 视频生成前提示词描述单镜头内可实现的运动和变化，但不执行生成。
